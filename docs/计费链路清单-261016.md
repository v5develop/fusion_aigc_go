> 来源：测试库 `fusion_aigc` 只读核对（2026-10-16）。线上库没有核，核对用 `deploy/sql/check-billing-online.sql`。
> 计费开关（`Mode`，部署时由 `deploy.env` 的 `BILLING_MODE` 写入）默认 off。**九个功能已接进提交 / 出结果 / 失败 / 删除（2026-10-16）**，

## 〇、计费接入点（代码里谁在什么时候动账）

三档开关（笔记、数字人、图片视频三个服务各自读 `Billing.Mode`，部署时统一由 `BILLING_MODE` 写入）：

| 档位 | 行为 |
|---|---|
| `off`（默认） | 什么都不做，不查库、不拦人 |
| `shadow` | 提交时照常算价、查权益，**只打日志不动账、不拦用户**；算价出错（缺配置、没权益）也只记 ERROR 日志，用来在上线前把"开了会拦谁"全暴露出来 |
| `on` | 真扣：提交时冻结，成功确认，失败退回；点数不够、没权益、缺配置都**拒绝提交** |

| 时机 | 做什么 | 备注 |
|---|---|---|
| 提交（用户点"生成"） | 冻结点数（`Hold`） | 余额不够 → 业务码 1008「点数不足，还差 N 点」；没开通该功能 → 1004「暂未开通该功能」；缺计费配置 / 命中未实现的计价规则 → 1000「暂时无法计费」并打 ERROR；冻结在落库之前，不够就不留记录 |
| 出结果成功 | 确认扣费（`Done`） | 一次出多张图部分成功时，按成功的张数确认，差额退回（档位 `settlement_type=PARTIAL` 才允许；整单档位一律全额） |
| 出结果失败 / 超时 | 退回冻结（`Fail`） | |
| 用户删除了生成中的任务 | 退回冻结 | 成品用户拿不到；已结算的单这里是空操作 |
| 过期没人结算 | 回收（`Reclaimer`，imagegen 服务里跑） | 只收我们自己的单（`golife:` 前缀）；图片类 30 分钟、视频类 200 分钟（要长于各功能自己的超时） |

预留单怎么找回：冻结在提交接口、确认退回在轮询器，所以请求号必须是库里能再拿到的值——

| 功能 | 请求号（biz_id = 用户编号_请求号） | 冻结时机 | 计量 |
|---|---|---|---|
| 海报、长图 | 客户端 `X-Request-Id` | 提交 | 张数 = 生成数量 |
| 动作迁移 | 客户端 `X-Request-Id` | 提交 | 按秒，**不知道动作视频多长**，用档位默认时长（见下） |
| 数字人口播 | 客户端 `X-Request-Id` | 提交 | 按秒 = 用户选的 15 / 30 秒 |
| 探店、短剧 | 出片的 task_id（每次出片都不同） | 点"确认出片"（构思不收费） | 按秒 = 15 / 30 |
| 爆款复刻 | 出片的 task_id | 点"确认出片"（解析不收费） | 按秒 = 解析出的原片时长 |
| 图文笔记 | 出图的 task_id | 点"确认生成"（构思不收费） | 张数 = 套图数量 |
| AI数字人 | 出片的 task_id | **配音出来之后**（时长要等配音才知道）；提交时先按最短 4 秒检查余额，明显不够就直接拒 | 按秒 = 配音实际时长 |

已知口径与限制：
- 动作迁移的时长：现在没有动作视频时长，按档位的默认时长算（测试库是 20 秒，约 120 点）。要精确得让导入动作视频时记下时长，再传进去。
- AI数字人：提交成功后，配音完成才冻结；如果这时点数已经不够（比如同时点了别的生成），记录会被标「失败」并提示点数不足，不会出片。
- AI定制形象（4 张）不在计费入口里，不收费。
- 分辨率不传，用档位默认；图片单价按"无分辨率"那行（10 点）。要按 2k / 4k 收费得把分辨率传进去。
- 删除生成中的任务会退点，但执行面那边的任务没有取消接口，会自己跑完（成本由我们承担）。

联调验证（本机，114 的计费配置副本 + 补配置脚本）：`deploy/scripts/billing-e2e-helper.sh seed|audit` 配合现有 `e2e-*.sh`，
服务以 `Billing.Mode: "on"` 启动，跑完核对：没有留在 HELD 的单、冻结为 0、账户余额与批次一致、总收入 = 余额 + 冻结 + 已消费。

## 三、代码门禁：缺配置不再静默放行

之前的行为与改动：

| 位置 | 之前 | 现在 |
|---|---|---|
| `price()` 算价 | 缺场景 / 档位 / 步骤 / 单价已经报错 | 保持报错；**新增：算出 0 点也报错**（单价写成 0、步骤全是只记成本，都不能当免费放过去） |
| `CheckAccess` 权益准入 | 入口没配计费方案时只打日志、**放行** | 返回 `ErrNoOffer`，**拒绝**，并打 ERROR 日志 |
| `Mode=off` 启动 | 静默 | 启动打 ERROR 日志：「所有生成任务不会扣点，正式上线前必须是 on」 |
| 上线前检查 | 靠人记得 | 新增 `billing-check` 工具：把 9 个入口 × 档位逐个真算一遍价，缺什么报什么 |

`billing-check` 检查项：
- 缺场景 / 档位 / 步骤 / 单价、算出 0 点 → ERROR。
- 命中未实现的计价规则 → ERROR。
- 云端档挂 lite 步骤、lite 档挂云端步骤 → ERROR。
- 能力码没有任何人被发放过 → ERROR。
- 一个档位多个收费步骤（会叠加扣费）→ WARN，需要人确认是不是有意。
- 场景没挂能力码 → WARN。

使用：
- `bash install.sh check-billing`：随时手工跑。
- `bash install.sh` 安装时自动跑；`deploy.env` 里 `BILLING_MODE=on` 且检查有 ERROR 时**中止安装**，`off` / `shadow` 只提示。
- 新增计费功能要把入口加到 `pkg/billing/audit.go` 的 `Targets`，否则检查覆盖不到它。

对测试库跑 `billing-check`，当前结果：

- ERROR：图文笔记、海报、长图缺场景。
- ERROR：动作迁移 cloud 档无步骤、lite 档找不到。
- ERROR：爆款复刻 lite 档无步骤，cloud 档挂了 lite 步骤。
- WARN：爆款复刻 cloud 档两个收费步骤叠加 360 点。

> 关于「线上告警」：门禁只能在提交时拒绝并打 ERROR 日志、在安装时报出来。没有接监控告警系统，要「第一时间发现」需要运维把日志里的 `billing:` ERROR 接进现有告警。
