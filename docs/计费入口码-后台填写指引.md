# 计费场景怎么填（给配置的人）

> 2026-09-27 · 页面：Fusion AIGC 后台 → **计费管理 / 计费场景**（表 `afv_billing_offer`）
> 对应《计费方案-扣点与入口码》第三节。

## 一、字段对应关系

「新增场景」弹窗里的字段 → 库字段：

| 弹窗字段 | 库字段 | 填什么 |
|---|---|---|
| 场景编码 | `offer_code` | **下划线**写法，如 `digital_human` |
| 场景名称 | `name` | 中文名 |
| 入口编码 | `entry_code` | **驼峰**写法，如 `digitalHuman` ← **我们代码里用的是这个** |
| 能力编码 | `feature_code` | 下拉选，见下表 |
| 分类 | `category` | 只有 `IMAGE` / `VIDEO` 两种 |
| 计费场景 | `billing_scene` | 只有 `IMAGE_GEN` / `VIDEO_GEN` 两种 |
| 状态 | `status` | `ENABLED` |

⚠️ **两个码不一样，别填成一个**。`offer_code` 是下划线、`entry_code` 是驼峰，
档位表是按 `offer_code` 关联的，入口调用是按 `entry_code` 找的。

⚠️ **只建场景还不够**。建完要点行首的 `+` 展开，配：
1. **档位**（`afv_billing_offer_variant`）——一个模型一档；
2. **计费步骤**（`afv_billing_charge_component`）——按张还是按秒在这里定；
3. 单价在左侧菜单 **计价规则**（`afv_model_pricing`）。

## 二、⚠️ 三个卡点：填之前得先解决

### 1. 模型表里没有 Seedance 2.5

产品定的视频价 **11 积分/秒**是按 Seedance 2.5 算的，但 `afv_ai_model` 里
**一条 2.5 都没有**，只有：

| id | code | 名称 |
|---|---|---|
| 3 | `xiaoqi-video-1.0-lite` | XQ Video 1.0 Lite |
| 4 | `doubao-seedance-2-0-260128` | Seedance 2.0 |
| 5 | `doubao-seedance-2-0-fast-260128` | Seedance 2.0 Flash |

→ 要先在「**模型管理**」里把 Seedance 2.5 建出来，再配单价。

### 2. 图片类的模型和单价对不上，差 17 倍

产品扣点表写的是 **GPT Image 2，1 积分/张**。但：

- `afv_ai_model` 里**没有 GPT Image 2**；
- 我们实际发给执行面的图片档位是 `max`，对应的应该是 `xiaoqi-image-1.0-max`（id 8）；
- 而它在 `afv_model_pricing` 里**现价 17 积分/张**（规则 id 9）。

**17 vs 1，差 17 倍。** 这个得产品和后端一起确认：到底用哪个模型、按哪个价。
在定下来之前，图片类三个场景（图文笔记 / 海报 / 长图）先别配。

### 3. AI文案没地方放

分类只有 `IMAGE` / `VIDEO`，能力编码里也没有纯文本生成的（只有 `ai_chat`，
它是 `TEXT_CHAT` 对话，不是我们这个"帮写文案"）。

→ 要么新增一个文本类的分类和能力码，要么**AI文案干脆不计费**。
建议后者：成本 0.005 元/次，1 积分收都算亏本收，不值得为它开一套配置。

视频类每个场景两档（云端 + lite），图片类一档。

| 场景 | 档位 | 模型 | 计量 | 单价 |

计费步骤（展开 `+` 里配）：

- 视频类：`component_type = DURATION`、`cost_type = BILLED`、`action_type = VIDEO_GEN`
- 图片类：`component_type = OUTPUT`、`cost_type = BILLED`、`action_type = IMAGE_GEN`
- 倍率 `price_multiplier` 都填 `1.0`

**结算方式**（档位上的 `settlement_type`）：

- 图文笔记 → **`PARTIAL`**（套图部分成功要按实际张数结算，失败的退钱）
- 其余全部 → `ALL_OR_NOTHING`

## 五点五、⚠️ 现有配置里有个矛盾，配的时候别照抄

`action_transfer` 的计费步骤写的是 **`OUTPUT`**（按产出数量），
它的单价却是 **`PER_SECOND`**（按秒）。两者打架。

我们的算价按**单价单位**为准（"8 积分/秒"这句话里的"秒"就在 `price_unit` 上），
所以不会算错。但**新配的时候请让两者一致**，免得以后谁看配置都要猜：

- 按秒的步骤 → `component_type = DURATION`
- 按张的步骤 → `component_type = OUTPUT`

## 五点八、⚠️ 还剩一个改名的小事

`action_transfer` 的两档叫 `action_transfer_cloud` / **`action_transfer_standard`**，
别的模块都是 `_cloud` / `_lite`。

我们的代码按**档次**选档位（找 `<场景编码>_cloud` / `<场景编码>_lite`），
因为两边模型码对不上——我们下发的是 `seedance2.5` / `lite`，
计费配置里是 `doubao-seedance-2-5` / `xiaoqi-video-1.0-lite-b6`，
而且计费那边把单价编进了模型码（`-b6`/`-b8`/`-b12`），**调价就会换码**，不能拿它当对接键。

所以请把 `action_transfer_standard` **改名成 `action_transfer_lite`**：

```sql
UPDATE afv_billing_offer_variant SET variant_code = 'action_transfer_lite'
 WHERE variant_code = 'action_transfer_standard' AND deleted = 0;
UPDATE afv_billing_charge_component SET variant_code = 'action_transfer_lite'
 WHERE variant_code = 'action_transfer_standard' AND deleted = 0;
```

（或者给它的 `quality_tier` 填 `lite` 也行，代码两种都认。
不改的话动作迁移的 lite 档会直接报「没有 lite 档」——**不会悄悄按云端价扣**。）

## 六、配完怎么验

**先自查**：把 `deploy/sql/check-billing-config.sql` 在测试库跑一遍，
一眼看出哪个入口码缺场景 / 缺档位 / 缺步骤 / 缺单价。

然后告诉我，我跑一条命令读配置算价（不动账）：

```
探店 15 秒 云端  → 应得 165
探店 15 秒 lite  → 应得 90
复刻 180 秒 云端 → 应得 2160
动作迁移 15 秒   → 应得 120
```

算不出来会直接报「入口码没有配置计费方案」，不会悄悄算成 0 让用户白嫖。
