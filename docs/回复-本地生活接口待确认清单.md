## A. 阻塞项

### A1. 海报、长图的模型 —— 已改

- **海报**：`GET /image-creations/options?kind=poster` 现在返回
  ```json
  {"models":[{"code":"max","label":"max"}], "default_model":"max"}
  ```
  `POST /image-creations` 也接收并校验 `model`（不传用默认）。
  执行面 78 支持 `mini` / `plus` / `max` 三档，**本版只开 max**（已和产品定过"档位一律 max"）。
  以后放开别的档位，你们不用改代码——options 会自动多出来。

- **长图**：执行面 76 **根本没有 `model` 参数**（对接文档里 76 的字段只有 `user_text` / `template_url` / `material_urls` / `size`）。
  所以 `kind=longImage` 的 options **不会有 `models`**，这不是没做完。
  ⚠️ **请把「没下发就拦住提交」这条改成只对海报生效**，否则长图会一直卡住。

### A2. 不选模板能否提交 —— 做不到，要产品定

对接文档写得很死：**76 的 `template_url` 必填、78 的 `template` 必填**。执行面收不到模板会直接报错，不是我们这边放不放行的问题。

所以「AI智能匹配」只能由**我们后端兜底挑一张模板**再发给执行面。要做的话需要产品先定：

1. 按什么挑？（随机一张 / 按用户选的「海报类型」筛完随机 / 固定一张默认模板）
2. 挑中的模板要不要在结果里告诉用户？

产品定了我这边改动不大。**在那之前，不带 `template_id` 提交会返回 `1001`「请先选择模板」**。

### A3. 预签名接收的视频格式 —— 已改

`POST /upload/presign` 现在收这 6 种，和 options 的 `video_formats` 一致了：

| 格式 | content_type |
|---|---|
| mp4 | `video/mp4` |
| mov | `video/quicktime` |
| avi | `video/x-msvideo` |
| mkv | `video/x-matroska` |
| flv | `video/x-flv` |
| wmv | `video/x-ms-wmv` |

你们用的四个 MIME 写法和我加的完全一致，不用改。网关代传 `POST /upload`（开发用）也一并加了。

## B. 视频复刻

### B1. generate 带提示词、模型、比例 —— 已改

```jsonc
// POST /video-creations/:id/generate
{
  "prompt": "改过的剧情文本",   // 选填，不传沿用解析结果；上限 20000 字
  "model":  "lite",            // 选填，取 options 的 models
  "size":   "16:9"             // 选填，不传让成片跟原片走
}
```

字段名就是你们用的这三个。三个都会**落库**，详情接口能读回来（刷新页面不丢）。

`GET /video-creations/options?kind=videoRemake` 现在也下发：

```json
{"models":[{"code":"doubao-seedance-2-0-260128","label":"seedance 2.0"},
           {"code":"lite","label":"XQ Video 1.0 Lite"}],
 "default_model":"doubao-seedance-2-0-260128",
 "sizes":[{"code":"9:16"},{"code":"16:9"}]}
```

⚠️ **`sizes` 故意没有 `default_size`**：不选就是"跟原片"，别自动选中一个。

### B2. AI优化剧情 —— 没有接口

`/copywriting/ai-write` 的 `scene` 枚举里现在没有合适的值。要做的话我加一个（比如 `scene=remake_script`，入参把原剧情放 `context`，返回 `text`）——**你们说一声我就加**，半天的事。现在提示「暂未开放」是对的。

### B3. `script` 的结构 —— 已改，现在是纯文本

之前它是「JSON 字符串」（外面裹了一层引号），所以你们 parse 出来是个字符串、当对象取键就取空了。**现在直接返回可读文本，不用 parse。**

内容是执行面 70 解析出来的剧情文本，实际长这样（Markdown）：

```
## 一、整体信息
【视频风格】：短视频带货
【总时长】：14.9 秒
...
## 二、人物与主要主体
## 三、分镜逐镜描述
### 分镜 01
【时间】：0.0 – 1.7
...
## 四、关键动作与事件时间轴
## 五、视觉参考标签
#短视频带货 #清新明亮 ...
```

⚠️ 但**这是模型生成的，结构不保证**。建议按 Markdown / 纯文本整段渲染，别按固定小节名解析。

⚠️ **同一个 `script` 字段在两类模块里形态不同**：
- 探店 / 短剧 → **JSON 对象**（`{"scenes":[...]}`），保持原样；
- 视频复刻 → **纯文本**。

按 `kind` 区分就行。

### B4. 话题标签 —— 不返回

详情和列表都没有标签字段。要加的话，标签得有来源——70 的解析文本末尾确实有一行 `#短视频带货 #清新明亮 …`，我可以抽出来单独给个字段，但**要产品先确认这是不是设计稿想要的那种标签**（那是画面风格标签，不是"#探店 #美食"这种内容标签）。

### B5. 解析中的标题和封面 —— 链接入口有了，上传入口仍然没有

**这条在写这份回复的过程中变了**：同事的链接解析服务已经给出来了，我已经接上。

- **链接入口**（`source=link`）：**`title` 提交那一刻就有**；`cover_url` 要等后台把封面转存完（几秒），轮询详情会补上。
  标题和封面来自解析服务（抖音/快手的标题通常就是文案），封面我们会**转存到自己的桶**——
  解析服务给的直链几小时就过期，不转存的话用户过一会儿再看就是裂图。
- **上传视频入口**（`source=upload`）：**仍然是空的**。用户传的就是个 mp4，要拿标题封面得抽首帧，这版没做。

所以判断逻辑建议按来源分：链接来源直接用，上传来源继续用文件名 + 占位图兜底。

另外链接入口现在**真的开放了**：`options.link_enabled` 会返回 `true`（前提是服务端配了解析服务地址）。
支持抖音 / 快手 / 小红书 / B站，**整段分享文案直接粘贴就行**（带口令、表情、话题标签都能认），不用让用户手动抠链接。

### C1. 计费 —— 这版不扣点，接口还在等

1. **价目和余额都在现有 Java 服务里**，不在我们这边。他们的扣费是两段式（提交冻结 → 成功确认 / 失败退回），单价按「入口码 → 档位 → 步骤 → 模型单价」算出来。
2. **但他们没有对外的扣点接口**，而且我们这十个模块的「入口码」还没在他们的计费表里登记。所以**要接计费，得他们先开接口 + 配价目**，这两件我在推。
3. 你们问的四条，我现在能确定的：
   - **点数不足返回 `1008`**（这个码一直在，新文档错误码表漏写了，我补上）；
   - 扣点时机会是**提交时冻结、成功后确认、失败退回**（对齐他们的口径）；
   - 「本次需要多少 / 还差多少」两个字段**我接的时候会带上**；
   - 单价从哪个接口给、余额从哪个接口取 —— **等他们的接口定了我第一时间同步**。

## D. 字段取值

**D1. 定制形象的 status** —— 对，`0` 生成中 / `1` 已完成 / `2` 失败，没有别的值。
两个补充：① `image_urls`（4 张）只有 status=1 才有值；② 成品转存失败时后端会**保持 0 重试**，所以可能长时间停在 0，轮询要有超时提示。
另外 `POST /digital-humans/portraits/:id/regenerate` **返回的是一条新记录（新 id）**，不是把老记录改回 0 —— 请用返回的新 id 继续轮询。

**D2. 肤色色值** —— 在 **`value`** 字段里，没有单独的 `color`。格式就是 `#F9DCCB` 这样：

```json
{"code":"fair","label":"白皙","value":"#F9DCCB"}
{"code":"natural","label":"自然","value":"#F0C3A0"}
{"code":"wheat","label":"小麦","value":"#E3A77F"}
{"code":"tan","label":"健康","value":"#D08E64"}
```

**D3. `image_ref` 的取值范围** —— 目前只会出现你们已经处理的这四个：`ENV_01`（门店图）、`ENV_02`（店内图）、`PROP_01`（道具/商品图）、`CHAR_01`（出镜人物图），以及用 `+` 连接的组合。因为**提交时最多就传这四张图**，剧本里不会引用不存在的素材。以后加了素材位我会提前说。

**D4. replan 改张数的字段名** —— 对，就是 `image_count`（和 `plan` 一样，选填）。

**D5. `note_type` 传中文名还是 code** —— **传中文名**（探店 / 种草 / 情感 / 知识）。后端不查字典，原样拼进提示词「笔记类型：xxx」。传 code 的话模型收到的就是 `explore`，效果会变差。
（注意这里和 `POST /notes/plan` 不一样，那个传 code。）

**D6. 话题带不带 `#`** —— **返回一律带 `#`**；**提交时带不带都行**：后端会先剥掉开头的 `#` / `＃` 再统一补一个，不会出现 `##`。同时会去空、去重（`#探店` 和 `探店` 算同一个）、按上限截断。

**D7. 笔记编辑页图片上限** —— 以 `options.max_edit_images` 为准（当前 3）。但实际生效的是 **`max(max_edit_images, 这条笔记生成出来的张数)`** —— 也就是说生成了 5 张的笔记，编辑时上限就是 5，不会逼你删图。设计稿写的 10 张需要产品确认后我改配置。

**D8. 动作迁移的成品视频地址** —— 对，在 **`image_urls[0]`**。`ImageCreation` 没有 `video_url` 字段，动作迁移固定生成 1 个，所以取第 0 个即可。（`input_image_url` / `input_video_url` 是入参，不是成品。）

**D9. `char_url`** —— 对，就是提交时的出镜人物图，而且**三种来源都会回填成最终图片地址**：
- `UPLOAD` → 用户上传的图；
- `PUBLIC` → **那个公共数字人的图**；
- `AI` → **该定制形象 `image_urls[image_index]` 那一张**。

前端不用自己记来源，详情里的 `char_url` 一律可以直接展示。不传 `portrait_source` 时为空串。

**D10. AI文案「带货」** ——
1. code 是 **`promotion`**。全量五种：`general` 通用 / `explore` 探店 / `promotion` 带货 / `knowledge` 知识 / `emotion` 情感。（运营可在后台改，仍请以 options 下发为准，别写死。）
2. 「商品卖点」放 `topic` —— **对**，`generate` 没有单独字段。

**D11. 风格和模型** ——
1. **对**，`styles` 是一组、不区分内容类型。设计稿里分两套的话，要么前端自己按内容类型过滤，要么告诉我，我给选项加个"适用内容类型"字段。
2. **对**，`generate` 不收模型参数，页面上只展示当前模型即可。

**D12. `target_words` 的上下限** —— **后端目前不校验**，传任意正整数都原样拼进提示词；传 0 或负数回落到默认 200。
**已补**：后端现在限 **50–2000**，越界返回 `1001`「字数请填 50–2000」。前端按同样的范围限制就行。

**D13. 自主撰写与列表** ——
1. `POST /copywriting` 保存的记录 `source = "MANUAL"`，`status` 直接是 `1`。`title` 不传的话后端取正文前 20 字，`word_count` 后端算。
2. `GET /copywriting` **会返回生成中（0）和失败（2）的记录**，列表不支持按 status 筛。
   ⚠️ 顺带说一句：笔记、图片、视频的列表都支持 `status` 筛选，**只有文案没有**。你们要是需要，我加一个 `status` 参数（默认不限）——比前端自己过滤好，不然分页 total 会对不上。要不要？

**D14. 生成历史 `derivatives`** ——

3. 列表项的 `id` 是 **素材库里那条素材的 id**，不是笔记 id / 生成记录 id。所以**现在这个 id 打不开你们的成品页**——真要交付的话我得改成返回业务 id，你们提需求时说一下要哪种。

## 另外几个你们没问但会踩的

1. **`status=1` 不等于全部成功**：多图场景（笔记套图、海报多张）只要有 1 张成功就是 1，`image_urls` 长度可能小于 `image_count`。展示时按实际数组长度来。
2. **转存失败时状态原地不动**：成品要从执行面的私有桶转存到我们的公有桶，转存失败会保持"生成中"等下一轮重试。所以轮询要有**最大时长兜底**，别无限转圈。
3. **视频复刻的链接入口**请用 `options.link_enabled` 判断要不要展示。配了解析服务才是 `true`；没配时调用会返回 `1006`「链接解析暂未开放」。
   链接解析失败的几种提示（都是 `1001`，直接展示 `msg` 即可）：链接不支持、作品里没有视频（图集）、超过 3 分钟、超过 50M。
