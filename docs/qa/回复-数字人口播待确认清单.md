## 2. 鉴权

1. **`X-User-Id` 填什么**：**待定**。联调阶段填任意正整数即可，数据按这个 ID 隔离。正式用哪套用户体系正在和另一个后端对齐。
2. **正式鉴权方案与时间**：**待定**（同上）。接口路径和参数都不会变，只换请求头。切换方式、是否有过渡期，定了再发。
3. **未登录 / token 失效**：HTTP **200**，`code=1002`，`msg`「未登录」。正式鉴权上线后也用这个码，端上遇到 1002 就触发重新登录。
4. **prod 是否还认 `X-User-Id`**：**不会**。开发模式只在联调环境开，正式环境一定关掉。

## 3. 上传

1. **presigned URL**：✅ **已按你们的建议实现**，新接口 `POST /api/v1/upload/presign`：

   ```
   请求  {"kind": "image", "content_type": "image/jpeg"}
   返回  {"put_url": "https://…?OSSAccessKeyId=…&Expires=…&Signature=…",
          "url": "https://…/aigc-life/image/…/xxx.jpg",
          "content_type": "image/jpeg",
          "expires_at": 1790051817000}
   ```

   前端把文件原样 PUT 到 `put_url`，**必须带 `Content-Type: <返回的 content_type>`**（签名包含它，不一致会 403），HTTP 200 即成功，然后把 `url` 作为 `image_url` 提交。
   前端拿不到任何密钥，也不用实现签名。已在真实 OSS 上验证：上传成功、公网可读、`Content-Type` 不一致时被拒。
   原来的 STS 凭证接口保留兼容，新接入请用预签名。
2. **对象 key**：后端生成，前端不用管。每次都是新的随机文件名，不会覆盖同名文件；扩展名和 `content_type` 一致。
3. **限制**：
   - 支持的类型：图片 `image/jpeg` `png` `webp` `gif` `heic`；视频 `video/mp4` `quicktime`。其他类型取地址时会返回 1001。
   - 大小由前端控制，后端不再校验。
   - `put_url` 30 分钟有效，一个地址只传一个文件。
4. **`kind`**：`image`（照片、背景图）和 `video`（动作迁移的动作视频）。口播里的背景也用 `image`；音频不需要前端上传。
5. **Content-Type**：必须带，而且要和返回的一致。成品链接按扩展名预览，正常打开。
6. OSS 桶已允许跨域 PUT（含 `Origin: null`），不需要额外配置。
