## 1. ❗ 各环境域名

文档只写了 `http://<host>:8888`，前缀 `/api/v1`。App 的 H5 离线包是「一次构建、四套环境通用」，
运行时按宿主当前连接的环境选域名，所以需要四个值：

| 环境 | 域名（含协议与端口） |
|---|---|
| dev | ？ |
| test | ？ |
| staging | ？ |
| prod | ？ |

另请确认：
- **是否有 https**。H5 从 `file://` 发出的请求受 Android `network_security_config` 与 iOS ATS 管辖，
  http 域名要逐个登记白名单；正式环境请务必 https。
- **是否允许跨域**。离线包页面的 Origin 是 `null`（`file://`），请确认网关对 `Origin: null`
  放行，并允许自定义头 `X-User-Id`、`X-Request-Id` 的预检（OPTIONS）。

## 2. ❗ 鉴权

文档说「每个请求都带 `X-User-Id`（开发模式；接正式登录后只换请求头，接口不变）」。

1. **`X-User-Id` 填什么**：乡选联盟的用户 ID 吗？还是本地生活自己的用户体系、需要先换一个 ID？
2. **正式鉴权的方案与时间**：
   - 是直接校验**联盟登录 token**（`Authorization: Bearer <联盟 token>`），还是要像 fusion 那样
     先用联盟 token 换一个本服务的 token？
   - 若要换 token，请给换取接口、有效期、过期时的错误码。
   - 预计哪个环境、什么时候切过去？切换期间两种头是否同时兼容？
3. **未登录 / token 失效的返回**：HTTP 状态码与 `code` 分别是什么？端上要据此触发重新登录。
4. **线上是否还接受 `X-User-Id`**：如果 prod 仍认这个头，任何人改一下请求头就能冒充别人，
   请确认 prod 一定关闭。

## 3. ❗ 上传：STS 直传 OSS

文档 4.1 的流程是：取 STS 临时凭证 → 前端直接 PUT 到 OSS → 用 `{base_url}/{key}` 提交。

App 现有的上传是原生统一传到联盟的 OSS，而你们**只接受 `aigc-local-life/image/...` 目录下的地址**，
所以口播页必须在 H5 里自己直传。几点需要确认：

1. **能否改为后端签好 URL**：由后端返回一个带签名的 PUT 地址（presigned URL，外加最终的 `url`），
   前端只管 PUT 文件。这样前端不需要拿 `access_key_secret`、也不用自己实现 OSS 签名算法，
   更简单也更安全。若可以，请给接口形状；若不行，请说明要求的签名版本（V1 / V4）。
2. **对象 key 规则**：随机文件名由前端生成是否可以？扩展名是否必须与内容一致？
   同名覆盖会不会有问题？
3. **限制**：图片允许的格式与大小上限各是多少？后端会不会再校验一次？
   （设计稿只写了「建议上传模特半身照片，增加成功率」。）
4. **`kind` 的取值**：除了 `image` 还有哪些（后续背景、音频是否会用到别的 kind）？
5. **Content-Type**：PUT 时是否必须带正确的 `Content-Type`？不带会不会导致成品链接无法预览？
