# 媒体资源：身份、存储位置、缓存与路由设计

状态：**已确认方案，部分已实施**。范围：fusion-aigc（Java）、fusion_aigc_go（媒体服务）、ai-gateway 三个子系统。

已实施：rid 寻址与桶内路径（`v1/<类别>/<yyyy>/<mm>/<对象键>[.<后缀>]`，rid → 路径靠私有桶索引对象 `idx/<对象键>.json`；删除对象时同步删索引）、类别与删除规则、`resources/urls`、直传两步接口、音频与字幕接口、按 rid 路由到所属实例（§4）、owner 按幂等键选择（§5）、实例 ID 启动查重与墓碑、下线命令（§8.1）。待实施：软删除（§8.5）。下文标注「待实施」或「待确认」的地方以此为准。

## 0. 目标与原则

**第一原则：媒体服务是唯一的媒体存储与处理中间件。** 所有媒体字节的下载、落桶、转存、处理、URL 签发、清理，只由媒体服务完成。Java 与网关只持有资源 ID，不持有字节，也不直接访问桶的读写。

**唯一目的：提效。** 减少系统内部反复的下载、存储、转存，消除链路传递中的时间瓶颈。任何设计决策，如果不能减少重复搬运，或者会增加链路时延，都不采纳。

1. **一个媒体资源只有一个真相来源**：对象存储（桶）。字节只在桶里有一份持久副本。
2. **系统内只交换引用，不交换字节**：三个子系统之间传的是资源 ID，不是文件、不是长期 URL。
3. **同一份字节在系统内最多下载一次**：生产它的实例把结果留在本地缓存，之后的消费者路由到它，命中缓存。
4. **访问方式是策略，不是存储位置**：签名还是公开，由服务商配置决定，按需签发，不把 URL 存进数据库。
5. **缓存只是加速，不是正确性的依赖**：任何缓存失效、实例宕机，都回落到桶，结果不变。

## 1. 身份模型

每个媒体资源有两个标识，职责分开：

| 标识 | 形式 | 作用 | 对谁可见 |
|---|---|---|---|
| `rid`（资源 ID） | `<实例 6 位 ID>-<类别>-<HMAC 派生的 26 位编码>`，例如 `a7k2zq-work-…` | 系统内部的唯一身份，Java、网关、媒体服务之间传它 | 仅内部 |
| `object_key` | `HMAC(密钥, "key|"+rid)` 的 26 位 base32；桶内路径为 `v1/<类别>/<object_key>` | 桶里的对象键，不包含 `rid`、不包含实例 ID | 可能出现在对外 URL 里 |

- `rid` 里嵌入了**所属实例（owner）**和**类别**。owner 是路由的依据（见第 4 节）；类别决定桶内前缀与删除规则。
- `rid` 的派生输入是类别与幂等键（见第 5 节），不是随机数，也不是 ULID。
- `object_key` 由 `rid` 经 HMAC 得到，媒体服务不需要查索引就能从 `rid` 算出键；对外 URL 里不会泄露 `rid`、实例 ID 或业务信息。
- 资源的**内容身份**是 `sha256`，它是字节的属性，不是资源的身份。同一份字节可以有多个 `rid`（例如同一个视频被两次注册），去重是可选的，由 Java 根据 `sha256` 决定是否复用已有 `rid`。

### 1.1 资源记录（完整身份信息）

每个资源的记录至少包含：

```
rid            资源 ID（内部身份，含 owner 实例与类别）
object_key     桶里的对象键（由 rid 派生）
class          类别：user | work | deliver | asset（与 rid 中的类别一致）
store          存储位置：private | asset_library | third_party（已实施，见 §11.1）
bucket         实际桶名（由 store + 环境决定）
sha256         字节的内容摘要
size, mime     字节大小、MIME
width, height, duration_s, fps, has_audio   媒体属性（探测得到）
retention      保留策略：user | work | deliver | asset
expire_at      到期时间（work、deliver 有；user、asset 为空）
parents[]      来源资源的 rid 列表（派生关系，用于溯源）
created_by     生产方：服务 + 操作（如 gateway/conform、java/register）
idem_key_hash  生产时的幂等键摘要
created_at
```

- **Java 数据库是权威的业务记录**：它保存 `rid`、业务归属、引用计数。
- **媒体服务的权威记录是对象本身**（目标形态，待确认）：资源的元数据写在对象的用户元数据和标签里（`x-oss-meta-rid`、`x-oss-tagging`），所以只要有 `rid`，就能 HEAD 到对象拿到全部属性，不依赖任何数据库。当前实现中 OSS 写入代码未见写入这两项，实际做法待确认。读侧目前是按 `rid` 派生的对象路径 HEAD 取字节数（`resources/urls` 的 `size`）。

注：§1.1 列出的是目标记录形态。当前接口返回的对象字段以 `media.api` 的 `ObjectRef` 为准（见 §11.1），`retention`、`expire_at`、`parents`、`created_by`、`idem_key_hash` 等字段尚未出现在接口中，待实施。

## 2. 每个存储位置里放的是什么

### 2.1 私有桶（`private`）

| 前缀 | 内容 | 保留 | 访问 |
|---|---|---|---|
| `v1/user/<object_key>` | 用户直传的原始输入 | 长期，任何流水线操作都不删 | 仅服务端签名读取 |
| `v1/work/<object_key>` | 流水线中间产物（规整、截剪、抽帧、供应商产出的临时副本） | 标签 `expire_at`，到期删除 | 仅服务端签名读取 |
| `v1/deliver/<object_key>` | 给第三方、且第三方只能用签名 URL 的产物 | 长期或按服务商有效期，到期清理 | 按需签名 URL（有效期由调用方指定，有上限） |

- 私有桶**永远不做公开访问**。用户上传到这里，和用户之间的访问也是按需签名。
- 用户直传与流水线产物分前缀（`user/` 与 `work/`），是为了生命周期互不影响：流水线清理 `work/` 时不会碰到用户原始输入。

### 2.2 公有桶

公有桶分两个桶（配置上区分，可以指向同一个物理桶）：

| 桶 | 前缀 | 内容 | 访问 |
|---|---|---|---|
| 素材库公有桶 | `v1/asset/<object_key>` | 素材库产物 | CDN 公开读取，长期 |
| 第三方公有交付桶 | `v1/deliver/<object_key>` | 服务商要求公有地址的交付产物 | CDN 公开读取，按服务商有效期清理 |

- 公有对象一旦写入就**无法收回访问**（已经发出去的公开地址无法撤销），所以公有交付只在服务商明确要求公有地址时使用，并且要在写入时就决定，不靠事后复制。
- 删除公有对象要同时做 CDN 刷新，这是清理流程的一部分。

### 2.3 本地缓存（每个媒体服务实例）

- 内容：最近使用的对象字节，按 `object_key` 索引，放在实例的临时目录。
- 性质：**只是副本**，可以随时丢弃。任何时候丢失都能从桶重建。
- 容量与淘汰：实际上限 = min(配置项 `InputCacheMaxBytes`，磁盘可用空间的 30%)，配置项默认 10 GiB（实现见 `app/media/disk.go` 的 `effectiveCacheCap`）。超过时淘汰空闲且最早过期的文件，正在使用的文件不删。同一 URL 的并发请求只下载一次，其余等待同一结果（实现见 `app/media/cache.go` 的 `acquire`，测试 `cache_singleflight_test.go`）。
- 生命周期：最后一次使用后保留 `InputCacheMinutes`；实例重启后缓存清空，不做持久化。
- **写穿透**：一个实例生产的资源（比如规整产物），字节写进桶的同时也留在本地缓存。这是命中率的关键：生产者手里本来就有字节。

**对象缓存（按 rid，已实施，`app/media/object_cache.go`）**：上面的输入缓存按 URL 缓存外部输入；按 `rid` 读取已落桶的对象（处理接口的 `rid` 输入、`register`、`resources/copy`）走另一套对象缓存，两者互不影响。

- 键：`rid`。条目同时记录 `store`、桶内路径与**版本**（OSS 为 ETag，本地实现为大小+修改时间）。`rid` 并不严格对应固定字节（同一幂等键在幂等记录过期后重跑、不同路由复用同一个幂等键、清理后同一键重新入库、直传签名地址在有效期内被重复使用，都会让同一 `rid` 指向新字节或新路径），所以命中要求三者全部一致。
- 每次读取的顺序：`objectPath`（索引）→ `checkReadable`（待删除标记，命中即 410）→ 向存储查版本（OSS 一次 HEAD）→ 版本一致才用本地文件，否则 / 对象不存在 / 查询失败都回落到与原来相同的 `Fetch`，取回后登记缓存。权威状态只在共享桶里，所以别的实例打的待删除标记、物理删除、覆盖写，都在本实例下一次读取时生效；本地副本永远不会绕过这两项检查。版本在 `Fetch` 之前查，取到的字节不会比记录的版本旧。
- 写穿透：`storeWithMeta` 写入成功（含清除待删除标记）后，用本次 PUT 响应的 ETag 作为版本登记（硬链接，跨文件系统时复制，临时名 + rename）。
- 容量：实际上限 = min(`ObjectCacheMaxBytes`（默认 10 GiB），磁盘可用空间的 20%)，与输入缓存的 30% 合计不超过一半；超过时按最近使用时间淘汰空闲条目，任务正在用的文件不删（允许暂时超出）；单个对象超过上限不缓存；空闲超过 `ObjectCacheMinutes`（默认 30）由后台清扫删除。`ObjectCacheMaxBytes` 或 `ObjectCacheMinutes` 为 0 时关闭。目录前缀 `media-cache-obj-`，崩溃残留由启动时的孤儿清理一并处理。
- 代价：命中仍要一次 HEAD 与一次待删除标记查询（与原来相同），省掉的是整份字节的下载。

### 2.4 网关

- 网关不持久化任何媒体字节。
- 上传给供应商时需要的字节，是通过签名 URL 临时取回的，用完即丢。
- `aig://` 从网关桶的引用，改为 `mr://<rid>`（见第 6 节）。

### 2.5 Java 服务

- 不存字节，不存 URL。
- 只存 `rid`、业务归属、引用计数。需要 URL 时现场向媒体服务申请（见第 3 节）。

## 3. URL 的签发（按服务商策略）

服务商的 URL 方式由 Java 的服务商配置决定，两种：

- `signed`：签名 URL，有效期由服务商要求决定（比如服务商拉取要 30 分钟内完成，就设 60 分钟）。
- `public`：公有 CDN 地址，只对位于公有桶的资源可用。

签发接口（已实施）：

```
POST /v1/mediasvc/resources/urls
{ "rid": "...", "store": "private" | "asset_library" | "third_party", "mode": "signed" | "public", "ttl_seconds": 3600 }
→ { "rid": "...", "object_key": "...", "store": "...", "mode": "signed", "size": 1234, "url": "...", "expires_at": "..." }
```

- 类别从 `rid` 推导，请求体不传 `class`。若传了，必须与 rid 一致，否则 `400 class_mismatch`。
- `public` 模式：资源必须在公有桶。如果资源只在私有桶，返回 `409 no_public_location`。是否要为公有交付**另外复制一份**，是 Java 的决定，媒体服务不自动复制。复制会产生新的 `rid`，`parents` 指向原资源，保证可溯源。复制接口当前未实现，待实施。
- `signed` 模式：有效期默认 3600 秒，上限 24 小时（服务端配置），超过返回 `400 invalid_request`，不截断。
- URL 不写进数据库，每次需要时重新签发。

## 4. 多实例下如何命中有缓存的机器

问题：有多个媒体服务实例，每个都有自己的本地缓存。如果请求随机分发，同一份字节会被重复下载到不同实例。

方案：**让资源 ID 携带所属实例，所有对这个资源的请求都路由到它的所属实例**。

当前实现：rid 携带所属实例。调用方（Java 与 Go 客户端）对 rid 键的路由是：**所属实例排第一**（从注册元数据 `instance_id` 找到它的地址），所属实例不在线时按 rendezvous 哈希顺序兜底；所属实例不持有缓存时，对象仍从共享桶读取，结果不变（见 `docs/api/media-service.md` 的「实例发现与注册」）。

1. **所属实例（owner）在资源创建时确定**：谁生产（或谁第一次注册）这个资源，谁就是 owner，`rid` 里嵌入 owner 的稳定实例 ID。
2. **实例 ID 是配置项，不随 IP 变化**：例如 `MEDIA_INSTANCE_ID=a7k2`，部署时固定，不用 IP 或主机名。
3. **路由规则**：调用方（Java、网关、其它实例）拿到 `rid`，解析出实例 ID，再从注册中心（r-nacos）查出该实例的地址，直接请求它。
4. **owner 不可达时**：任何实例都可以从桶里取字节，这时是一次缓存未命中，代价是一次桶下载（比从原始 URL 下载便宜，而且不依赖供应商）。这是降级，不是错误。
5. **外部请求的路由**：对于还没有 `rid` 的请求（比如 `ingest` 一个新 URL），按 URL 做一致性哈希选实例，选中的实例成为新资源的 owner，`rid` 里写的就是它。

这样做的效果：
- 生产方留有缓存（写穿透），消费方按 `rid` 路由回生产方，**同一份字节在正常路径下只在桶和 owner 之间各流动一次**。
- 不需要共享缓存、不需要分布式锁。对象缓存不依赖"资源不可变"：每次命中前都向桶核对版本与待删除标记（见 §2.3「对象缓存」），桶里的对象被改写或删除时本地副本自动失效。

**需要注意的边界**

- owner 实例下线后，它的缓存就没了，但资源仍在桶里，所以只会慢，不会错。
- 实例 ID 不能复用：一个 ID 只能属于一个实例。下线的实例 ID 在一段时间内不能分给新实例，否则旧 `rid` 会路由到错误的机器（它会找不到对象，回落到桶，结果仍然正确，但语义上混乱）。

## 5. 幂等（跨实例、跨重启）

**决定：`rid` 由幂等键派生，不用随机数，不用指针。**

- `rid = <所属实例 6 位 ID> "-" <类别> "-" <HMAC(服务端密钥, "rid|"+类别+"|"+幂等键) 的 26 位 base32>`（已实施，见 `app/media/identity.go`）。类别进入派生输入，同一幂等键在不同类别下得到不同的 rid。
- 没有幂等键的操作（如抽帧）以内容 sha256 代替幂等键。
- 同一个幂等键的重试，生成的 `rid` 和 `object_key` 完全相同，对象只会被覆盖写，不会产生第二份。
- 所属实例不取"当前接收请求的机器"，而是按幂等键在注册中心的存活实例 ID 集合上做 rendezvous 哈希算出来（实现：`app/media/owner.go` 的 `pickOwner`）。候选集合包含本实例；查询结果缓存 5 秒；注册中心不可用时沿用上次结果，从未成功过则只有本实例。成员不变时同一幂等键总得到同一 owner，因此重试得到同一个 rid；成员增减时只有映射到变动实例的键会换 owner，这是这种哈希的标准性质。**取舍：成员变化的窗口内，同一幂等键的重试可能得到新的 rid，对象会多一份（覆盖写不会发生，因为路径不同）。** 这个窗口由注册中心的心跳与健康检查决定，运维应避免在实例滚动发布期间重放大批任务。
- 不需要幂等指针，也不需要处理中标记，没有"写了对象却没写指针"的中间状态。
- 当前的内存幂等缓存仍保留，作为同一实例内的快速返回；跨实例、跨重启的正确性由 ID 派生保证。

## 6. 三个子系统的交互

### 6.1 Java（fusion-aigc）

- **用户直传**：Java 申请私有桶的预签名上传（`user/` 前缀）。上传完成后调用 `register`，把对象键和大小交给媒体服务，媒体服务分配 `rid` 并写入对象元数据。Java 保存 `rid`。
- **素材读取**：Java 不再下载。直接对 `rid` 发指令（探测、截剪、规整等），拿回新的 `rid`。
- **交付**：Java 按服务商策略发指令：`mode=signed` 时产物写进私有交付前缀；`mode=public` 时写进公有交付桶。写入位置在生产时就决定。
- **URL**：需要时调用签发接口，不存库。
- **清理与归档**：Java 根据引用计数决定删除，通过标签（`expire_at`、`retention`）让桶的生命周期规则执行，或者直接发删除指令（删除前必须确认无引用）。

### 6.2 媒体服务（fusion_aigc_go）

- 唯一的字节读写方：下载来源、落桶、探测、处理、签发 URL、清理。
- 所有操作的输入是 `rid`，或者外部 URL（只用于 `ingest`，之后立即注册成 `rid`）。
- 输出是 `rid` 加元数据，不返回字节。

### 6.3 ai-gateway

- 规整、截剪、探测：输入 `rid`，输出新的 `rid`。
- 需要给供应商 URL 的：调用签发接口，`mode=signed`，有效期覆盖供应商拉取时间。
- 供应商产物：直接把供应商的 URL 交给媒体服务 `ingest`，得到 `rid`。网关**不再自己存一份**，`aig://` 废弃，改为 `mr://<rid>`。
- 上传给供应商时需要字节的（比如 Atlas 的 `uploadMedia`）：经签名 URL 下载一次，用完即丢。**是否能省掉这一步，取决于供应商能否直接读 URL，需要实测。**

## 7. 对象存储访问的策略总结

| 位置 | 写 | 读 | 删 |
|---|---|---|---|
| 私有 `user/` | 用户直传（预签名）、`register` | 服务端签名 | 永不删（除非用户注销，走单独流程） |
| 私有 `work/` | 媒体服务 | 服务端签名 | 标签到期 |
| 私有 `deliver/` | 媒体服务（按 signed 策略写入） | 按需签名 URL | 按服务商有效期 |
| 公有 `asset/` | 媒体服务（素材库产物） | CDN 公开 | Java 决定，同步 CDN 刷新 |
| 公有 `deliver/` | 媒体服务（按 public 策略写入） | CDN 公开 | 服务商有效期到期，同步 CDN 刷新 |
| 本地缓存 | 媒体服务（读取时、写穿透） | 媒体服务 | LRU / TTL |

## 8. 已确认的决策

1. **实例 ID**：每个部署位置一个随机生成的 6 位小写字母数字 ID，首次部署时生成，写进部署配置并持久化，容器重建沿用。实现：注册前查询注册中心，同一 ID 的存活实例在别的地址上时**拒绝启动**（退出码 1）；运行中发现冲突也停止服务并以非零退出。注册中心暂时连不上不致命，后台重试，且每次重试前都重新检查。同一地址的重启允许。下线用 `media-svc -retire <id>`：ID 写入注册中心的墓碑配置项 `media-instance-tombstones`，此后任何实例用该 ID 启动都被拒绝；重复下线幂等。
2. **幂等语义**：`rid` 由幂等键派生（见第 5 节），重试天然覆盖，不用指针，不用处理中标记。
3. **公有交付复制**：不自动复制。生产时按服务商策略决定位置；资源已在私有桶而服务商要公有地址时，Java 显式发复制指令，媒体服务返回新 `rid` 并记录 `parents`。没有显式指令时，签发公有地址返回 `409 no_public_location`。
4. **本地缓存容量**：上限取"磁盘可用空间的 30%"与"配置硬上限（默认 10 GiB）"中较小者。LRU 淘汰，正在使用的文件不删。同一对象的并发取数单飞行（single-flight），只下载一次。只用磁盘，不用内存。具体数字等运维提供磁盘规格后确认。
5. **删除权威**：Java 决定，媒体服务执行，且采用软删除：先标记 `pending_delete`，宽限期（默认 7 天）后由生命周期规则真正删除，期间 Java 可撤销。删除指令携带 Java 的引用计数快照，媒体服务只做标签状态的校验，不自行判断引用。（软删除与宽限期已实施，见本节末尾；删除指令携带引用计数快照仍待实施：当前 `delete` 不携带快照，删除前的引用确认仍由 Java 负责。当前已实施的删除规则见 §11.7。）
**软删除的实现（已实施）**：`delete` 不删字节，只登记待删除标记。标记是与数据对象同桶的独立状态对象 `pending-delete/<桶内路径>`：OSS 下元数据 `x-oss-meta-delete-after` 记到期时间，创建时带 `x-oss-forbid-overwrite`，已存在则读回原到期时间、不覆盖；本地实现是同名文件，内容为到期时间。选它而不选对象标签，理由有三：（a）标签不能按条件列举，清理只能全桶扫，而状态对象可以按前缀分页列举；状态对象与数据同桶、原子创建，可靠持久；（b）本地实现用同样的文件结构，测试与开发与线上行为一致；（c）不依赖桶的生命周期规则：宽限期由服务端清理任务（`app/media/sweep.go`，周期与宽限期都是配置项）完成，运维未配置生命周期规则也正确，将来配置了也只是冗余兜底。清理先删对象再清标记，失败留着下一轮重做，全程幂等。被标记的对象读取（rid 或 key 输入、`resources/urls`）返回 `410 resource_deleted`；`restore` 在宽限期内撤销，过期返回 `409 grace_expired`。用户输入与历史 `sha256/` 路径不接受标记（delete 直接 403，清理再拦一次）。

6. **`ingest` 的 URL 输入**：保留，仅作外部入口。成功后立即返回 `rid`，之后系统内只使用 `rid`。外部 URL 经服务商配置的域名白名单，并保持现有的 SSRF 检查。

## 11. 接口契约（第二批，三个子系统共用）

各子系统只依赖下列字段，**不得解析或拼接对象键**。

### 11.1 媒体结果（所有写操作的 `object`）

```
object.rid      资源 ID（内部身份，后续所有操作都用它）
object.class   user | work | deliver | asset
object.key      桶内路径 v1/<class>/<yyyy>/<mm>/<object_key>[.<ext>]（仅媒体服务内部与运维使用，业务层不解析）
object.store    private | asset_library | third_party
object.sha256, size, mime, duration_s, width, height, fps, has_audio
```

### 11.2 输入引用

各操作的 `source` 三选一：

- `{"rid": "<rid>"}`：系统内资源（首选，所有内部链路都用它）。类别从 rid 推导，不传 class。
- `{"key": "<路径>", "store": "..."}`：仅用于兼容历史数据与运维。
- `{"url": "https://..."}`：仅作外部入口，成功后立即返回 `rid`。

### 11.3 签发地址

`POST /v1/mediasvc/resources/urls`，body `{rid, store, mode: signed|public, ttl_seconds}`，返回 `{rid, object_key, store, mode, size, url, expires_at}`。`class` 可省略，传了必须与 rid 一致。调用方每次需要时现签，不保存地址。

### 11.4 直传注册（两步，Java 不选对象路径）

1. `POST /v1/mediasvc/resources/upload-target`，body `{class: "user", store: "private", idem_key, mime, size}`，返回 `{rid, object_key, upload_url, expires_at}`。`upload_url` 是签名 PUT 地址，调用方用它直接上传字节到私有桶。
2. 上传完成后 `POST /v1/mediasvc/resources/register`，body `{rid}`。媒体服务校验对象存在与大小，返回 object 结果（含 rid）。

class 仅允许 `user`。Java 只保存 rid。

### 11.5 幂等

同一个 `Idempotency-Key` 的重试，返回同一个 `rid`。调用方的幂等键由它自己的业务单号派生（例如 `<任务ID>:<步骤>`）。没有幂等键的操作（抽帧）以内容 sha256 作为派生输入。rid 的派生公式见第 5 节。

### 11.6 错误码

沿用契约 §7。新增：`not_found`（404）、`no_public_location`（409）。

### 11.7 rid 寻址的读写约定

- **写**：写操作在 `object` 里返回 `rid`、`class`、`key`。同一幂等键返回同一 `rid`（派生规则见第 5 节）。
- **读**：`source` 传 `{"rid"}`，类别由 rid 推导，请求体不传 `class`。`store` 只对 `deliver` 类别有意义：`third_party` 读第三方桶，缺省读私有桶。
- **地址**：`POST /v1/mediasvc/resources/urls` 只传 `rid`（`class` 可省，传了必须一致，否则 `400 class_mismatch`）、`store`、`mode`、`ttl_seconds`。`store` 必须与类别配对：`asset` → `asset_library`；`user`、`work` → `private`；`deliver` → `private` 或 `third_party`。
- **删除**：`{"rid"}`。`user` 类别与历史 `sha256/` 路径返回 `403 forbidden_purpose`，不删除。
- 类别对应的存储：`user`、`work` → 私有桶；`deliver` → 私有或第三方桶；`asset` → 素材库桶。

### 11.8 mr:// 引用约定

- **网关的输入引用**：`mr://{rid}`，**不带扩展名**。网关向媒体服务现签地址，请求里不传 class。
- **Java 内部约定**：私有交付回填为 `mr://{rid}.{扩展名}`。扩展名只用于判断产物类型，**寻址只看 rid**。读侧经 `resources/urls` 现签，有效期 600 秒，不存库。
- 这是 Java 与网关之间的约定，不是媒体服务契约的字段。媒体服务不解析 `mr://` 字符串，只接收 rid。
- 旧的 `aig://` 引用只读兼容，直到所有引用迁完（见第 10 节）。
