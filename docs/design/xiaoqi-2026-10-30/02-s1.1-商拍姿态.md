# s1.1 商拍换装 / 姿态复刻（Agent B 产出，浓缩）

## 结论
- 只有「反推提示词」现成：Python 标准库 HTTP 服务（8090），唯一上游 DeepSeek（deepseek-flash, chat/completions + image_url, response_format json_object）。切图执行/组图/生图/队列/计费/历史/资产/OSS/鉴权全要我们做。
- .1（3867 行）= 商拍基线（crop-plan/crop-check/analyze-batch、按件面料、多段锁定）；.3（2776 行）= 姿态基线（表情指令、重试 4 次）。.3 没有切图/批量路由（会转发到 23.95.119.229:10000 上游）。建议以 .1 为基线并入 .3 的 ~25 行姿态差异（README 建议的方向反了）。
- 前端实际：每「模特×张数」一次 aiModelTryon（num=1，单 modelImageUrl）；每姿势一次 aiPostureFission。后端必须按提交批次缓存切图/analyze/source，否则 81 任务 → 300+ 次视觉调用。
- 指南示例代码有 bug（pick_images 跨单品按角度去重违反 D3；garments[:6] 丢第 7-9 张；role 缺失 KeyError；crop-check 截断索引错位）。
- 建议：Python 当内部 sidecar（删静态服务/billing/PRISM_EMBED/上游转发，只留 /api/status、pose/source、pose/prompt、reverse/analyze、analyze-batch、crop-plan、crop-check；只监听内网），Go 做编排、裁图、生图。Go 重写约 4000–5000 行、3–4 周、53 处正则含 3 处 RE2 不支持断言，暂不重写。

## 商拍 payload（前端实测）
imageUrls[服装首图,模特]（兼容位勿用）; modelImageUrl; garmentImages[{url, role(中文单品名/'整套'), angle front/back/side/detail/flat/unknown}]; items[] top/bottom/dress/outer/shoes/accessory/bra/panties ≤3（互斥：裙↔上/下；文胸↔上衣/裙；内裤↔下装/裙）; setMode one/two（1 件也传）; lengths/sleeves {itemKey:str}; fabric "上衣：真丝；鞋子：皮革"; prompt(→notes ≤3000); model; resolution 1K/2K/4K; aspectRatio; num=1。
上限：每件 6 角度槽，3 件共 9 张；模特 1–9；每位张数 1–9；≤81 任务；费用 单价×模特×张数。
后端需推断：category（单件 items[0]，多件 compose）、deep=true、palettes 等。

## 商拍链路
1 收单编号 g-<item>-<angle>-<seq>/m-<i>，单品按 items 顺序，角度 front→back→side→detail→flat→unknown，下载 ≤10MB，转 data URL
2 crop-plan {category, items, images[{role,angle,data}]} → plans[{index, angle, garment_box, crops[{label(带单品前缀), box[x,y,w,h] 0-1, confidence}]}], meta.mode keypoints/per-item/候选表（候选表需客户端传 candidates，指南没写；合影'整套'走这条很可能只剩兜底框）。只处理前 6 张 → 需分批。
3 裁图（我们）：归一化×像素，4% 内边距，短边<256 放大，JPEG q90，role='局部细节'
4 crop-check {items[{label,data}]} ≤12 → results[{index,ok,confidence}]；只删 ok=false&&conf≥0.85；失败不阻断
5 组图：主图(look/compose ≤6，其他 ≤4/≤2)→细节(max(1, 9-主图-1) 按单品轮询)→模特 1 张最后；sha1 去重；≤9
6 analyze {category,items,images,set_mode,fabric,notes,length_class,sleeve_class,lengths,sleeves,look_lengths,palettes,deep} → {prompt, meta{degraded,vision,...}, warning}；analyze-batch + models[{id,label,data}] ≤9, concurrency 1-6 → results[{index,model_id,prompt,meta,warning,error?}]。降级链 视觉→文字→模板。
7 生图 POST /api/tryon/generate（未实现）{modelImage(图1), garmentImages(图2..N), prompt, resolution, aspectRatio, num:1} → {image, run_id, elapsed_ms, cost_usd}；prompt 首行加图序声明正文不动；并发 3；只重试 429/5xx/超时 1.2/2.4/4.8s；幂等 job+model+shot；超时 crop/analyze 120s generate 300s；上传图上限 14（Seedream 10）。

## 姿态
前端：人物 1 + 姿势 1–9，每姿势一任务 imageUrls=[人物,姿势], prompt(全局+本张拼), resolution 默认 '1k'(小写), aspectRatio, num=1, model。无 mode/count。
三接口：POST /api/pose/source {image} → {source{has_person,gender_age,face,...,pose,note}} 422 无人/未成年；POST /api/pose/prompt {source,image,notes?,mode?short} → {prompt, pose{orientation_deg 0/45/90/135/180,...,face_visible,near_side}}；POST /api/pose/generate {source(图1),poseImage(图2),prompt,model{id}} → {image,run_id,elapsed_ms,cost_usd}（PRISM 文档口径不同：model{name,ratio,resolution}, 响应 {model,status,image,elapsed_ms}）。
source 按图 sha1 缓存一次；压缩 原图 1600px 姿势 1400px；服务端单张 ≤12MB，body ≤24MB；反推并发 9 生图 3。
提示词长版 4300–5500 字纯拼接无 LLM 二次生成；短版不用。表情指令 .3 独有（16 强表情词触发）。
模型 id 映射：前端 通用/GPT/Banana/Seedream vs 姿态页 nano/sunburst/seedream。

## 验收必过
C3 框合法；C4 细节前缀不串件；D1 images ≤9；D2 主图→细节→模特(1 张最后)；E4 面料按件；E9/F3 prompt 逐字一致（仅多首行图序）；F2 图序声明；G4 source=图1 poseImage=图2。
I 可观测：每步 JSON 日志 job_id/step/ms/images/crops/degraded/cost；状态机 queued→cropping→prompting→generating→done/failed；不记 base64/Key/完整 prompt。
