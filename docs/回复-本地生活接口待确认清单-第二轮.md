## 1. 比例

```
GET /image-creations/options?kind=poster    → sizes 6 种不变，default_size = "2:3"
GET /image-creations/options?kind=longImage → sizes = ["1:3"]，default_size = "1:3"
```

你们现在的兜底逻辑（下发里有 1:3 就用它）可以保留，但已经不需要兜底了。

## 4. 文案列表按状态筛

```
GET /copywriting?status=1     # 只要已完成的（「选择AI文案」弹窗用这个）
GET /copywriting?status=0     # 生成中
GET /copywriting?status=2     # 失败
GET /copywriting             # 不传 = 全部（和以前一样，不影响现有调用）
```

- 参数名 `status`，取值就是列表里的那三个状态码；
- **不传或传 `-1` 都是不限**，所以「我的文案」页照旧不传即可；
- `total` 会跟着筛选变，分页不会对不上。

## 5. 生成历史 —— 本期交付

```
GET /copywriting/:id/derivatives?kind=all&page=1&page_size=20
```

```json
{"code":0,"msg":"ok","data":{"total":3,"list":[
  {"id":128,"kind":"poster","size":"2:3","cover_url":"https://…/p.png",
   "result_url":"https://…/p.png","is_video":false,"create_time":1790755825451}
]}}
```

**三件事都改了**：

1. **`id` 换成业务记录 id** —— 笔记 id / 图片生成记录 id / 视频记录 id / 数字人 id，直接用它打开对应的成品页。（以前给的是素材库 id，打不开。）
2. **成品尺寸**：给的是 **`size` 比例**（`"2:3"` / `"9:16"` / `"16:9"`），不是像素宽高。
   各业务表里本来就没存像素尺寸，而判断横竖版用比例更直接。
   ⚠️ **笔记和数字人没有比例**（那两个表没这个字段），会返回空串——这两类按竖版处理即可。
3. **口播算进来了**，`kind` 枚举现在是 7 个：

| kind | 对应 | 打开哪个详情接口 |
|---|---|---|
| `note` | 图文笔记 | `GET /notes/:id` |
| `poster` | AI海报 | `GET /image-creations/:id` |
| `long_image` | AI长图 | `GET /image-creations/:id` |
| `voiceover` | 数字人口播 | `GET /image-creations/:id` |
| `digital_human` | AI数字人视频 | `GET /digital-humans/:id` |
| `explore_video` | 探店视频 | `GET /video-creations/:id` |
| `promo_drama` | 带货短剧 | `GET /video-creations/:id` |

> 你们「数字人口播」Tab 原来查的是 `digital_human`，现在改成 `voiceover` 就对了。
> 多出来的 `poster` / `long_image` 是顺带能给的——设计稿里没有这两个 Tab，要不要展示你们定，不展示就别传这两个值。

### ⚠️ 这条要你们配合改：提交时带上 `copywriting_id`

**关联关系不是后端能自己猜出来的** —— 用户从「选择AI文案」挑了一条文案，只有你们知道是哪一条。所以四个提交接口都加了一个**选填**字段：

| 接口 | 加的字段 |
|---|---|
| `POST /notes/plan` | `copywriting_id` |
| `POST /image-creations`（海报 / 长图 / 口播） | `copywriting_id` |
| `POST /video-creations`（探店 / 短剧） | `copywriting_id` |
| `POST /digital-humans` | `copywriting_id` |

**从「选择AI文案」进来的就带上这个 id，没带就是空**——不带不会报错，只是这条成品不会出现在那条文案的生成历史里。

另外：**生成历史只返回已完成的成品**。生成中和失败的不返回（这个列表是拿来点开看成品的），所以不用处理那两种状态。
